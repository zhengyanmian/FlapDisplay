# 翻牌显示器显示网页 — 可行性研究

日期：2026-09-28 · 状态：**可行，建议做成 MCEF 软依赖（可选前置）**

---

## 一、结论（TL;DR）

| 方案 | 可行性 | 画质 | 交互 | 体积代价 | 结论 |
|------|--------|------|------|----------|------|
| ① MCEF（内嵌 Chromium）软依赖 | ✅ 高 | 真实网页渲染 | 翻牌上只读镜像 | 用户自装（约 80-200MB） | **推荐** |
| ② 自带无头浏览器截图轮询 | ⚠️ 中 | 截图级（有延迟） | 无 | 需外部 Chrome | 不推荐 |
| ③ HTML 抓取转纯文本/摘要 | ✅ 高 | 文字排版（无图） | 无 | 零依赖 | 可做降级方案 |
| ④ 自研 HTML 解析器+渲染器 | ❌ 低 | - | - | 开发量巨大 | 放弃 |

**推荐路径**：把 MCEF（Modrinth: `mcef` 2.1.6-1.21.1，NeoForge，LGPL-2.1）作为**可选前置**，与 Net Music 同一模式——装了就解锁「网页」媒体源，没装不影响现有功能。

## 二、方案① 详细分析（MCEF）

### 现状调研（2026-09-27 检索确认）
- MCEF 2.1.6-1.21.1 已发布 NeoForge 1.21.1 版本（Modrinth 版本 ID `euXLgkSB`），72 万+下载，两年前更新后稳定
- 已有成功先例：**Ultimate Browser**（1.21.1 NeoForge，要求 NeoForge 21.1.220+）和 **MineChromium** 都基于 MCEF 实现了完整浏览器——证明「Chromium 渲染 → MC 纹理」这条链路在 1.21.1 上能跑通
- Maven 坐标：`maven.modrinth:TObQ0HxZ:euXLgkSB`（Modrinth Maven 可直接依赖）

### 与本模组的契合点
1. **URL 分发链路现成**：网页就是「一种新的媒体类型」。现有 `MediaRenderRegistry` 发包已把媒体 URL 同步到客户端，网页源只需新增一个 type，服务端零改动。
2. **纹理管线现成**：视频管线（后台解码 → DynamicTexture 上传）可直接复用——把「解码器输出帧」换成「MCEF onPaint 回调输出像素」。
3. **渲染叠加点现成**：`FlapDisplayRendererMixin` 的叠加矩形绘制不用动，网页纹理和视频纹理走同一条路。
4. **转速/ESC 暂停/孤儿回收规则自动继承**。

### 集成草图
```
客户端：
  WebPageSource (DisplaySource)
      └→ MediaRenderRegistry 发包（type=web, url=...）
  客户端 MediaManager：
      └→ 若 MCEF 已加载：创建离屏 browser（软依赖反射或独立 loader 模块）
      └→ onPaint 回调 → 缩放到翻牌纹理尺寸 → DynamicTexture
      └→ 复用视频的节流帧率（网页默认 2-5 fps 足够，页面加载瞬间可提帧）
```

### 关键限制（必须写进功能说明）
- **翻牌上只能看，不能点**：翻牌显示器是物理方块，没有鼠标焦点。交互只能在「网页预览 Screen」里做（MCEF 支持键鼠注入），翻牌面只做只读镜像
- **仅客户端渲染**：每个玩家的客户端各自开一个浏览器实例看同一 URL；联机时服务端只是转发 URL，不做渲染
- **内存代价**：Chromium 实例约 150-300MB 内存；建议限制「同时显示网页的翻牌数」或共享一个 browser 实例切换 URL
- **JS 重页面吃 CPU**：默认限 720p / 5fps（沿用现有 videoMaxDim/videoFps 思路）
- **MCEF 首次启动会解压 CEF 运行时**（约 80-200MB 到游戏目录），需在文档里说明

### 实施前的验证铁律（按项目惯例）
写第一行集成代码之前，先 `javap` 验证 MCEF 2.1.6 的实际公开 API（从 Modrinth Maven 拉 jar）：
- Browser 创建入口（`MCEFClientHelper`/`MinecraftChrome` 之类）与 `loadURL` 签名
- onPaint 回调注册方式与像素格式（BGRA/RGBA、stride）
- 是否支持无头离屏 browser（不打开浏览器 Screen 也能渲染）
- 软依赖加载方式：MCEF 类不能出现在我们自己的类签名里（参照 Net Music 的降级模式，`isLoaded()` 探测 + 独立 `WebPageCompat` 类隔离）

## 三、方案②③ 说明（非推荐但留档）

**② 无头浏览器截图轮询**：外部 `chrome --headless --screenshot` 定时截图 → 当作图片 URL 播放。缺点：延迟秒级、依赖用户装 Chrome、多客户端各自轮询浪费。唯一优点是零模组代码风险——如果只是想「显示一个页面的静态快照」，这条一天就能做出来。

**③ HTML 转文本**：抓取 HTML → 去标签 → 按现有文字管线显示（文字是 Create 翻牌的原生能力！）。零新依赖、性能零负担，适合「显示 wiki 摘要 / 股价 / 公告」类需求，但不是「真网页」。**可以作为 ① 不可用时的自动降级**。

## 四、建议的实施顺序

1. **P0 验证**：拉 MCEF jar → javap API → 写 10 行 demo 在 HUD 上渲染 baidu.com（半天）
2. **P1 最小可用**：WebPageSource + 单例 browser + 翻牌只读镜像 + 2fps（1-2 天）
3. **P2 打磨**：预览 Screen 交互、多翻牌共享实例、降级到文字模式、配置项（webFps/webMaxDim）（1-2 天）
